# DigiCloset Visual System

## Brand Statement

DigiCloset is a calm, premium mobile editorial outfit-memory app.

It should feel like entering a private wardrobe memory, not opening a shopping app, inventory tool, or analytics dashboard.

The product exists to help users:

- save complete looks
- revisit combinations that worked
- organize pieces around those outfit memories
- move through the app with a soft, personal, image-led rhythm

## Visual North Star

The visual direction for DigiCloset is:

> A calm, premium, mobile-first editorial wardrobe memory app.

It should feel:

- private
- warm
- soft-luxury
- image-led
- composed
- editorial
- mobile-native

It should not feel:

- ecommerce
- shopping-heavy
- cart or checkout oriented
- dashboard-like
- admin-like
- social-feed-like
- AI-gimmicky

## Current App Structure Notes

Before the 3G refresh phases:

- the current app already uses a warm neutral palette
- the current app already prefers rounded surfaces and image-led cards
- the current app already keeps Wardrobe more closet-like than table-like
- the current app still has a stronger utility feel than the new references
- the current app still uses more repeated white surfaces and rail blocks than the references
- the reference set pushes the app toward:
  - stronger arch/curve framing
  - more editorial title treatment
  - calmer page tops
  - fewer visibly "componentized" sections
  - more phone-screen composition discipline

## Reference Interpretation

These references are layout, rhythm, typography, spacing, and mood guidance. They are not pixel-perfect implementation requirements.

### 02 Wardrobe Reference

Borrow:

- search near the top inside a calm curved header context
- compact horizontally scrollable chips
- wardrobe sections that feel like editorial category tiles, not raw lists
- strong image-led category entry points
- separation between wardrobe sections and saved outfit memories
- uncluttered page rhythm

Do not copy:

- exact top icons or profile affordances
- any category counts that the app cannot support truthfully
- overly static tile composition if it harms real browsing utility

### 03 Capture Reference

Borrow:

- curved header and centered lockup
- very clear primary question around how to capture the outfit
- reuse-first block before manual creation
- selected-pieces state presented simply and calmly
- preview card that keeps outfit memory visual
- one strong final CTA anchored low

Do not copy:

- decorative controls that are not supported
- unnecessary steps that slow down quick save
- any rigid multi-panel desktop layout

### 04 Suggestions Reference

Borrow:

- calmer, more editorial top composition
- one strong "for today" feature card before rails
- thoughtful secondary rails for occasion, seasonal rotation, and favorites
- suggestion language that feels curated, not automated hype
- soft metadata pills

Do not copy:

- "style profile" if it implies a larger feature than the app currently has
- unsupported recommendation logic or fake personalization claims
- any busy retail-promo composition

### 05 Outfit Detail Reference

Borrow:

- strong hero image treatment
- left/right image and metadata balance on larger screens, but still mobile-native
- concentrated metadata with icons and generous spacing
- a single calm action bar
- clear "pieces in this outfit" strip
- black bottom CTA as the strongest next step

Do not copy:

- unsupported "wear this outfit" behavior if it implies something beyond mark-worn and revisit
- decorative icon rows that dilute the actual actions
- exact piece-brand metadata if not available

### 06 Piece Detail Reference

Borrow:

- full-piece hero image first
- large curved lower information surface
- metadata as soft pills instead of hard info cards
- clear reuse framing through "outfits using this piece"
- edit as primary action and remove as quieter secondary action

Do not copy:

- unsupported usage-count claims unless backed by real data
- exact category badges if they reduce clarity for normalized DigiCloset labels

## Visual Identity

### Mood

DigiCloset should feel like:

- a wardrobe journal
- a quiet dressing companion
- a personal closet memory space
- editorial fashion organization without commerce pressure

### Composition

- mobile-first vertical storytelling
- one major focal block per page before secondary rails
- curved top surfaces and soft frame transitions
- less "stack of modules"
- more "continuous page with deliberate pauses"

### Interface Character

- soft edges
- warm light backgrounds
- restrained accents
- quiet metadata
- generous whitespace
- image-led hierarchy

## Color Direction

Primary direction:

- ivory
- linen
- warm white
- charcoal
- taupe
- brass
- muted sage only as a restrained support accent

Guidelines:

- keep the canvas warm and paper-like
- prefer off-white surfaces over bright pure white when practical
- reserve deep charcoal or black for:
  - primary CTA
  - select active states
  - high-emphasis text
- use brass/taupe as subtle line, icon, or accent color
- avoid introducing bright blue or purple accents into the main product refresh

## Typography Direction

### Headings

- editorial serif-style direction
- larger, calmer, more spacious headings
- used for:
  - page titles
  - hero statements
  - section headlines where emphasis matters

### Supporting text

- clean sans-serif
- compact but breathable line length
- clear contrast against warm backgrounds

### Labels

- quiet uppercase or small sans-serif labels
- used sparingly
- never let labels overpower outfit imagery or page titles

## Surface and Card Rules

- prefer curved surfaces that feel integrated into the page
- avoid heavy nested card stacks
- not every section needs its own boxed treatment
- one strong image surface is often better than many framed blocks
- when a card is needed:
  - keep it soft
  - keep borders faint
  - keep shadows light
- outfit cards should carry more emotional and visual weight than clothing-piece cards

## CTA and Button Rules

- primary CTA:
  - black or charcoal pill
  - white text
  - centered or strongly anchored
- secondary CTA:
  - ivory or white pill
  - charcoal text
  - light border only when necessary
- destructive actions should remain quieter than primary memory actions
- never use bright, synthetic-looking call-to-action colors

## Bottom Dock Rules

- bottom dock must stay mobile-native and sculpted
- it should feel like part of the product shell, not a web nav bar
- icons should be simple and calm
- active state should be obvious but not loud
- keep the dock consistent across app pages
- auth pages should not show the dock

## Image Treatment Rules

- imagery should feel wardrobe-real and soft-editorial
- product surfaces should prefer:
  - outfit flats
  - hanger or mannequin-like styling
  - closet vignettes
  - clean wardrobe still-life treatments
- avoid:
  - shopping promo energy
  - influencer/social-feed framing
  - busy collage treatment
  - dark dramatic fashion-ad visuals
- image-led cards should have room to breathe
- image crops should favor clarity over abstraction

## Form and Input Rules

- inputs should feel light and warm
- use rounded rectangles or pills with subtle borders
- keep field count visually calm
- suggestion and chip inputs must stay supportive, not dominant
- form pages should remain mobile-reachable with strong single-primary-action hierarchy
- avoid admin-form density

## Empty State Rules

Empty states should feel:

- calm
- encouraging
- product-aware

Empty states should not feel:

- technical
- apologetic
- dashboard-like

Do:

- explain what kind of memory or wardrobe content belongs there
- point toward the next emotionally correct action

Do not:

- use sterile CRUD language
- over-explain the system

## Page-Specific Rules

### Home

Home should:

- open with one strong outfit-led hero moment
- keep weather compact and supportive
- prioritize recent memories and favorite combinations
- feel like the user is returning to their wardrobe memory, not checking metrics

Home should not:

- become a dashboard
- stack too many equally weighted modules
- lead with operational summaries

### Wardrobe

Wardrobe should:

- feel like entering a digital closet
- keep search and filters quiet and compact
- use stronger category and section imagery
- let pieces feel spatially grouped
- keep saved outfit memories visible as real anchors

Wardrobe should not:

- become grid-admin heavy
- feel like inventory software
- overexpose controls before content

### Outfit Memory / Capture

Capture should:

- make outfit memory feel primary
- make reuse obvious before duplication
- keep creation paths clear
- support image-first and text/manual paths without clutter

Capture should not:

- feel like a wizard
- become a giant form wall
- treat quick-add tools as equal to outfit memory

### Suggestions

Suggestions should:

- feel curated and quiet
- open with one strong recommendation moment
- support it with a few thoughtful rails
- preserve explainability

Suggestions should not:

- sound like fake AI
- overclaim personalization
- mirror Home too closely

### Outfit Detail

Outfit Detail should:

- lead with the saved look
- make metadata secondary but elegant
- show pieces clearly and compactly
- keep actions close and calm

Outfit Detail should not:

- split into many utility panels
- foreground editing over memory

### Piece Detail

Piece Detail should:

- frame the piece as part of the wardrobe story
- show its metadata softly
- clearly connect it back to outfit memories

Piece Detail should not:

- feel like a database record page
- outshine outfit detail in hierarchy

## Visual Refresh Guardrails

Every 3G implementation phase must:

- preserve auth and user isolation
- preserve backend and frontend data flows
- preserve existing route behavior
- preserve outfit-memory-first hierarchy
- run build checks
- run mobile viewport checks
- compare against reference screenshots when possible
- avoid feature expansion

## Do Not

- no ecommerce language
- no sales banners
- no cart or checkout patterns
- no analytics dashboards
- no dense admin tables
- no fake AI language
- no giant redesign dump in one phase
- no desktop-first split layouts as the main app experience
- no blue or purple CTA drift
- no decorative noise that competes with outfit imagery

## Recommended Working Method

Implement the 3G phases one page at a time.

For each phase:

1. inspect the current page and target reference
2. refresh only the necessary components
3. preserve working product logic
4. run build
5. run mobile viewport checks
6. compare against the reference screenshot when possible
7. update docs and commit the checkpoint
